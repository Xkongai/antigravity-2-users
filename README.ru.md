## Зачем

Десктопное приложение Antigravity позволяет войти только в один аккаунт Google одновременно. Учётные данные хранятся в связке ключей macOS вашего пользователя и в `~/.gemini/`. Если запустить вторую копию, поменяв только `--user-data-dir`, она обычно открывается под **тем же** аккаунтом: бэкенд читает `$HOME`, а не каталог данных Electron.

Типичные причины держать два профиля:

- **Работа отдельно от личного.** Код, аккаунт и обязательные расширения компании в одном окне, личные проекты — в другом.
- **Разделение клиентов.** Фрилансер может держать рабочее пространство, настройки и историю каждого клиента отдельно.
- **Тесты с чистого листа.** Пробуйте новые расширения, настройки или предварительные сборки в одноразовом профиле, не трогая повседневное окружение.
- **Обучение и демонстрации.** Показывайте экран из чистого демо-аккаунта, пока ваш настоящий аккаунт продолжает работать.

## Как это работает

```
                    your Mac (one macOS user)
 ┌──────────────────────────────┬───────────────────────────────────────┐
 │ Antigravity.app (main)       │ "AG Profile B.app" (launcher)         │
 │                              │   └─ runs the SAME Antigravity binary │
 │ HOME = ~                     │ HOME = ~/.ag-profile-b                │
 │ data = ~/Library/Application │ --user-data-dir = ~/.ag-profile-b/    │
 │        Support/Antigravity   │   Library/Application Support/...     │
 │ ~/.gemini, ~/.antigravity    │ ~/.ag-profile-b/.gemini, .antigravity │
 │ keychain: login.keychain-db  │ keychain: ~/.ag-profile-b/Library/    │
 │                              │   Keychains/login.keychain-db         │
 └──────────────────────────────┴───────────────────────────────────────┘
        shared on purpose (symlinks): Desktop · Documents · Downloads
        optional (--link-dev): .gitconfig · .ssh · .zshrc · .zprofile · .npmrc
```

1. **Отдельный HOME.** Ярлык задаёт `HOME=~/.ag-profile-<id>`. Всё, что приложение хранит в `~` (`.gemini`, `.antigravity` вместе с расширениями, кэши), теперь хранится там.
2. **Отдельный профиль Electron.** `--user-data-dir` указывает внутрь этого HOME, поэтому окна, настройки, хранилище и блокировка единственного экземпляра тоже разделены.
3. **Отдельная связка ключей.** Установщик создаёт `~/.ag-profile-<id>/Library/Keychains/login.keychain-db` со **случайным** паролем. Этот пароль хранится в вашей обычной связке ключей входа как элемент `antigravity-2-users`. Связка профиля настроена так, чтобы не блокироваться автоматически, поэтому фоновое обновление токенов продолжает работать и после сна.
4. **Приложение-ярлык.** `osacompile` собирает маленькое приложение AppleScript `AG Profile <ID>.app`. Оно запускает `~/.ag-profile-<id>/.ag2u/launch.sh`, который разблокирует связку профиля и затем через `exec` запускает настоящий исполняемый файл Antigravity. Иконка копируется из установленного у вас Antigravity во время установки, локально на вашем Mac, и никуда не распространяется. Приложение получает ad-hoc-подпись и по желанию добавляется в Dock.

Основная установка Antigravity не изменяется.

## Требования

- Ожидается, что работает на macOS 13 и новее (Apple silicon или Intel; на реальном железе пока не проверено), со стандартными системными утилитами `bash`, `python3`, `security`, `osacompile` и `codesign`
- Установленное десктопное приложение Antigravity, по умолчанию в `/Applications/Antigravity.app`
- Учётная запись администратора, чтобы писать в `/Applications`. Без прав администратора используйте `--app-dir ~/Applications`.
- Второй аккаунт Google для входа

## Установка

```bash
git clone https://github.com/Xkongai/antigravity-2-users.git
cd antigravity-2-users
./install.sh            # or: ./install.sh --link-dev --name b
```

Что делает установщик, по шагам:

1. Проверяет, что вы на macOS и что Antigravity установлен.
2. Создаёт `~/.ag-profile-b` (права 700) и добавляет туда ссылки на «Рабочий стол», «Документы» и «Загрузки». С `--link-dev` также добавляет ссылки на конфигурационные файлы git, ssh и оболочки. Настоящие файлы никогда не перезаписываются, повторный запуск безопасен.
3. Генерирует случайный пароль для связки ключей, сохраняет его в вашей связке ключей входа, создаёт и разблокирует связку профиля и отключает её автоблокировку.
4. Записывает `~/.ag-profile-b/.ag2u/launch.sh` и `config`, создаёт `/Applications/AG Profile B.app`, копирует иконку и подписывает приложение ad-hoc-подписью.
5. Сохраняет резервную копию настроек Dock в `~/.ag-profile-b/.ag2u/dock-backup-*.plist` и добавляет ярлык рядом с Antigravity. Чтобы пропустить этот шаг, укажите `--no-dock`.

macOS может один раз спросить, разрешить ли `security` использовать элемент `antigravity-2-users`. Выберите **Разрешать всегда**.

## Использование

1. Откройте **AG Profile B** из Dock, Launchpad или `/Applications`.
2. При первом запуске откроется чистый Antigravity, в котором вы ещё не вошли. Войдите во второй аккаунт. Если браузер передаёт вход не тому окну, см. [возврат после входа](#после-входа-в-браузере-открывается-не-то-окно).
3. После этого оба окна можно держать открытыми одновременно. У каждого свой вход, настройки, расширения и история.
4. Чтобы открыть один и тот же проект в обоих, используйте «Файл → Открыть папку» в каждом окне. «Рабочий стол», «Документы» и «Загрузки» видны из обоих окон, и любой другой абсолютный путь тоже работает.

Можно запускать и из терминала — это удобно для отладки. Дополнительные аргументы передаются в Antigravity:

```bash
./scripts/launch.sh --name b
./scripts/launch.sh --name b ~/Documents/my-project
```

Для дополнительных профилей: `./install.sh --name c` создаст `~/.ag-profile-c` и `AG Profile C.app`.

## Параметры

`install.sh`

| Параметр | По умолчанию | Значение |
|---|---|---|
| `--name <id>` | `b` | Идентификатор профиля (`a-z`, `0-9`, `-`). Данные хранятся в `~/.ag-profile-<id>`, ярлык называется `AG Profile <ID>.app` |
| `--app-source <path>` | `/Applications/Antigravity.app` | Какое приложение Antigravity запускать |
| `--app-dir <dir>` | `/Applications` | Где создать ярлык, например `~/Applications` |
| `--no-dock` | выкл. | Не трогать Dock |
| `--link-dev` | выкл. | Также добавить ссылки на `~/.gitconfig`, `~/.ssh`, `~/.zshrc`, `~/.zprofile`, `~/.npmrc` и `~/.config/git` |
| `-h`, `--help` / `-V`, `--version` | | Справка / версия |

`uninstall.sh`

| Параметр | Значение |
|---|---|
| `--name <id>` | Какой профиль удалить (по умолчанию `b`) |
| `--app-dir <dir>` | Где был создан ярлык (по умолчанию `/Applications`) |
| `--purge` | Без вопросов удалить также данные профиля, его связку ключей и сохранённый пароль (профиль выйдет из аккаунта) |
| `--keep-data` | Удалить только ярлык и значок в Dock |

`scripts/launch.sh [--name <id>] [аргументы Antigravity…]` и `scripts/verify.sh [--name <id>]` по умолчанию используют `b`.

## Проверка изоляции

```bash
./scripts/verify.sh --name b
```

Проверка только читает данные и выводит лишь **имена** элементов, никогда не секреты:

- запущенные процессы, использующие `--user-data-dir` этого профиля
- настройки связки ключей профиля (должно быть `no-timeout`) и её элементы (`svce` / `acct`)
- элементы Antigravity, Gemini и Jetski в вашей связке ключей **входа**
- имена файлов в `~/.gemini` и в `~/.ag-profile-b/.gemini`

**Что должно получиться:** после входа в профиль B его элементы появляются в связке ключей **профиля**, а файлы токенов — в `~/.ag-profile-b/.gemini`. Элементы основного аккаунта остаются в связке ключей входа.
Если элементы профиля B оказались в вашей связке ключей входа, значит, macOS на вашей системе не использует связку профиля. Пожалуйста, [создайте issue](https://github.com/Xkongai/antigravity-2-users/issues) и укажите версии macOS и Antigravity. Проверить можно и вручную: **Связка ключей** → Файл → Добавить связку ключей… → `~/.ag-profile-b/Library/Keychains/login.keychain-db`.

## Обновление

- **Обновления Antigravity:** ничего делать не нужно. Ярлык запускает приложение, которое лежит по пути `--app-source`. Если иконка устарела, снова запустите `./install.sh`; его можно запускать сколько угодно раз, вход при этом сохраняется.
- **Этот инструмент:** `git pull && ./install.sh --name b` с теми же параметрами, что и раньше. Данные и связка ключей профиля используются повторно.
- **Переход с раннего прототипа** (`Antigravity Pro 2.app`, `~/.antigravity-pro2-home`): прототип использовал фиксированный, публично известный пароль связки ключей. Удалите `/Applications/Antigravity Pro 2.app` и его значок в Dock. Затем либо удалите `~/.antigravity-pro2-home` и заново войдите в новом профиле, либо перенесите папку в `~/.ag-profile-b` перед запуском `./install.sh`; тогда установщик заменит старый пароль случайным.

## Удаление

```bash
./uninstall.sh                 # asks whether to delete profile data
./uninstall.sh --keep-data     # remove launcher + Dock entry only
./uninstall.sh --purge         # remove everything for profile b, no questions
./uninstall.sh --name c --purge
```

Останавливаются только процессы, запущенные с `--user-data-dir` этого профиля. Основной Antigravity, его данные и ваша связка ключей входа не затрагиваются (кроме элемента `antigravity-2-users` при `--purge`).

## Частые вопросы

**Это песочница?** Нет. Оба профиля работают под одним и тем же пользователем macOS с одинаковыми правами на файлы. Разделяются **аккаунты и состояние приложения**; это не граница безопасности.

**Не перепутаются ли аккаунты после перезагрузки?** Не должны. Каждый профиль читает свой HOME, свой каталог данных и свою связку ключей. Проверьте это на своём компьютере с помощью `verify.sh`.

**Почему профиль B видит мой «Рабочий стол» и «Документы»?** Они подключены в HOME профиля символическими ссылками, чтобы вы могли открывать свои проекты. Всё, что лежит вне HOME профиля, и так доступно по абсолютным путям.

**В терминале профиля B не работают git или SSH.** В его HOME нет `.gitconfig` и `.ssh`. Перезапустите установку с `--link-dev` или настройте их отдельно для этого аккаунта.

**Не находятся `brew`, `node` или `pyenv`.** В HOME профиля нет `.zshrc`. Используйте `--link-dev`; кроме того, ярлык добавляет `/opt/homebrew/bin` и `/usr/local/bin` в PATH.

**Можно запустить больше двух?** Да, по одному `--name` на профиль.

**Изменяется ли Antigravity.app?** Нет. Инструмент только читает исполняемый файл и копирует иконку.

## Устранение неполадок

### «AG Profile B» повреждено или не может быть открыто
Переподпишите ярлык и снимите атрибут карантина:
```bash
codesign --force --deep --sign - "/Applications/AG Profile B.app"
xattr -dr com.apple.quarantine "/Applications/AG Profile B.app"
```
Или щёлкните по приложению правой кнопкой → Открыть.

### Ярлык ничего не открывает
Запустите `./scripts/launch.sh --name b` в Терминале, чтобы увидеть ошибки. Проверьте, что `--app-source` указывает на существующее `Antigravity.app`.

### Значка в Dock нет или он появился дважды
Перетащите приложение из `/Applications` в Dock вручную или перезапустите установку с `--no-dock`. Чтобы восстановить Dock: `defaults import com.apple.dock ~/.ag-profile-b/.ag2u/dock-backup-<time>.plist && killall Dock`.

### После входа в браузере открывается не то окно
Оба профиля — это одно и то же приложение, поэтому macOS отправляет возврат после входа `antigravity://` той копии, которую выберет сама, обычно основной. Обходные пути:
1. Закройте основной Antigravity, войдите в профиле B, затем снова откройте основной. Это нужно сделать только один раз: вход сохраняется.
2. Если страница входа предлагает код или URL для вставки в приложение, вставьте его в профиле B.

### macOS постоянно спрашивает пароль связки ключей
Выберите **Разрешать всегда** для `security` / `antigravity-2-users`. Если связка профиля всё равно блокируется, выполните `security set-keychain-settings ~/.ag-profile-b/Library/Keychains/login.keychain-db` или снова запустите `./install.sh`.

### Профиль B внезапно вышел из аккаунта или не показывает модели
Откройте его заново через ярлык — это снова разблокирует связку ключей. Затем запустите `verify.sh`. Если у связки профиля задан тайм-аут, снова запустите `./install.sh`.

## Известные ограничения

- **Пока не проверено на реальном железе.** Скрипты проходят shellcheck и во время разработки были прогнаны от начала до конца на Linux с имитацией утилит macOS. Ни одна версия ещё не проверялась на настоящем Mac с актуальной версией Antigravity. Считайте инструмент экспериментальным и сообщайте, что видите.
- **Нет гарантии**, что macOS действительно сохраняет секреты профиля B в связку профиля, когда меняется только `HOME`; поведение может отличаться в разных версиях macOS. Именно для этого и нужен `verify.sh`.
- Возврат после входа `antigravity://` может попасть не в то окно (см. выше).
- Пароль связки ключей передаётся `security` в командной строке, поэтому на долю секунды он виден другим процессам вашего пользователя.
- Только macOS. Windows и Linux не поддерживаются.
- Внутреннее устройство Antigravity (расположение файлов, процесс входа) может измениться в любом обновлении и сломать этот подход.

## Безопасность

- Каждая связка профиля использует случайный пароль из 48 шестнадцатеричных символов, который хранится в вашей собственной связке ключей входа. Ничего не зашито в код, и ничего не покидает ваш Mac.
- Пока вы в системе, связка профиля не блокируется автоматически. Благодаря этому обновление токенов продолжает работать, но это же означает, что после разблокировки её может прочитать любой процесс, запущенный от вашего пользователя. Это та же модель доверия, что и у связки ключей входа.
- Каталог профиля создаётся с правами `700`.
- Скрипты никогда не используют `sudo`, ничего не скачивают, не меняют системные настройки, кроме Dock (с предварительной резервной копией, шаг можно пропустить), и никогда не трогают `Antigravity.app`.
- Прочитайте все скрипты перед запуском. Они короткие.

Нашли проблему безопасности? Пожалуйста, создайте на GitHub приватное security advisory, а не публичный issue.

## Участие

Issue и PR приветствуются, особенно **отчёты о проверке на реальном Mac** (версия macOS, чип, версия Antigravity, вывод `verify.sh` со скрытыми адресами почты).

- Пишите на Bash 3.2 (версия, которая поставляется с macOS) и следите, чтобы код проходил `shellcheck -S style install.sh uninstall.sh scripts/*.sh`.
- Поддерживайте переводы README в соответствии с `README.md`.
- Никаких материалов Google в репозитории.
